# ADR-0006: A separate laboratory of small executable propositions

**Status:** Proposed, 2026-10-29. Branches `feat/lab-*`; draft PRs #12 onwards.

## Context
The essay holds four experiments, each built and argued with care. Many more questions about indexing, community, history and collective memory deserved a working test, but adding them to the essay would turn a story into a catalogue. We wanted a place where ideas can be built quickly, fail openly, and be compared, without changing the essay or its conclusions.

## Decision
1. **A separate route family, `/lab/`.** The footer is the essay's only link to it. Story routes are unchanged.
2. **One catalogue, many free-form pilots.**
   - `src/lab/catalogue/<family>.ts` holds browsable metadata per pilot (`LabEntry`).
   - `src/lab/catalogue/critique.ts` holds the lead's assessments and status changes, kept apart so the builders' own readings stay in the record.
   - Each pilot's component and CSS are its own. The shell (`LabShell`) frames a pilot and prints its notebook; it never styles the pilot.
   - There is no universal experiment engine.
3. **One dynamic route, prerendered.**
   - `src/routes/lab/$n/index.tsx` serves every pilot. The prerender crawler finds the pages through the index's links.
   - The route's loader and head read only `src/lab/catalogue/heads.ts`. TanStack keeps loaders and heads in the entry chunk, and importing the catalogue or the pilots there put 1 MB on every story page.
4. **Pages-safe file names.** `vite.config.ts` strips leading underscores from chunk names, because the dynamic route produced `_n-….js`, which GitHub Pages' Jekyll step would drop.
5. **A browser contract, not a rendering contract.**
   - Each pilot marks one control `data-probe` and one output `data-observe`; `scripts/lab-check.mjs` checks that acting on one changes the other, along with focus, overflow, reduced motion and no-JS rendering.
   - Developed specimens add a behaviour check in `scripts/specimens/` that reproduces their finding through the interface.
6. **Frozen data stays frozen.** Pilots read Four Words v1 and the community fixtures but never write them; `tests/frozen.test.ts` pins the v1 digests. Re-rankings in the lab are demonstrations, not evaluation runs.

## Alternatives considered
- **Sixty route files.** Explicit, but repetitive; the route tree would grow by sixty entries for no behavioural gain.
- **A generic experiment component with configuration.** Rejected: it would have produced sixty variants of one interface, which the brief ruled out.
- **Lazy-loading each pilot.** Not needed yet. The lab's pilot chunk (about 290 kB, 86 kB compressed) loads only on lab pages. Revisit if the lab grows.
- **Embedding pilots in the essay.** Deferred to editorial review: candidates are listed in `docs/lab/EVALUATION.md`.

## Consequences
- **Bundle cost.** Lab CSS (about 120 kB) and the pilot chunk load only on lab routes. The entry chunk grows by about 10 kB, for the titles map and the index route stub.
- **Regeneration.** `heads.ts` must be regenerated when a title or question changes; a test fails until it is. The evaluation table is regenerated by `scripts/lab-evaluation.mjs`.
- **Test time.** `npm run browser` now also runs 60 pilots at three widths, so it takes several minutes.
- **No reader testing.** Every finding in the lab comes from building and using the pilots ourselves.
